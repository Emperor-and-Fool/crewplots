## Overview

The core issue is that **connect-redis\@9.0.0** only accepts a **Node Redis** or **ioredis** client instance—that client must fully implement the store interface (methods like `get`, `set`, `del`, `expire`, etc.) in order for session data to be saved and retrieved correctly ([npmjs.com][1]). Third-party packages (e.g. “redis-client”) or half-baked custom clients will break because they don’t expose the exact async methods that connect-redis expects ([npmjs.com][2]).

## Use the Official `redis` Package

1. **Install** the supported library:

   ```bash
   npm install redis@^4
   ```

   Don’t use outdated or unmaintained packages such as `redis-client` (last updated 10 years ago) ([npmjs.com][3]).

2. **Import and create** the client, then **connect** before wiring up your session store:

   ```ts
   import { createClient } from 'redis';
   const client = createClient({ url: process.env.REDIS_URL });
   client.on('error', console.error);
   await client.connect();
   ```

   This ensures you have a live connection and the promised-based commands (`get`, `set`, etc.) are available ([redis.io][4]).

## Example Integration with Express-Session

```ts
import session from 'express-session';
import connectRedis from 'connect-redis';
import { createClient } from 'redis';

const client = createClient({ url: process.env.REDIS_URL });
client.on('error', console.error);
await client.connect();  // Must connect before using the store :contentReference[oaicite:4]{index=4}

const RedisStore = connectRedis(session);

app.use(session({
  store: new RedisStore({ client }),    // Pass the official client instance :contentReference[oaicite:5]{index=5}
  secret: process.env.SESSION_SECRET,
  resave: false,
  saveUninitialized: false,
  cookie: { secure: false, maxAge: 1000 * 60 * 60 } // 1-hour TTL
}));
```

Each session operation (`store.get`, `store.set`, `store.destroy`) will now map to the Redis client’s `get`, `set`, and `del` commands, with TTL handling via `expire` or `PX` options ([redis.io][4]).

## Wrapping a Custom Client

If you must use a bespoke or proxy client, **wrap** it so that it implements the required interface for connect-redis:

```ts
class WrappedRedisStoreClient {
  constructor(private base: any) {}

  async get(key: string) {
    return this.base.get(key);
  }

  async set(key: string, val: string, options: { ttl?: number }) {
    if (options.ttl) {
      // PX for milliseconds, EX for seconds
      await this.base.set(key, val, { PX: options.ttl });
    } else {
      await this.base.set(key, val);
    }
  }

  async del(key: string) {
    return this.base.del(key);
  }

  async expire(key: string, ttl: number) {
    return this.base.expire(key, Math.ceil(ttl / 1000));
  }
}
const wrappedClient = new WrappedRedisStoreClient(customBaseClient);
app.use(session({
  store: new RedisStore({ client: wrappedClient }),  // Now meets the interface :contentReference[oaicite:7]{index=7}
  /* … */
}));
```

This guarantees your client offers the exact methods (`get`, `set`, `del`, `expire`) and signatures that **connect-redis** invokes under the hood ([npmjs.com][5]).

---

If you switch from Postgres to Redis but still see session IDs changing on each request or missing data, it almost always means the **store layer** isn’t actually persisting or retrieving the serialized session. Fixing the client–store interface as above will restore persistent sessions in both the browser and API calls.
